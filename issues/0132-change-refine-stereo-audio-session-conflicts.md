# stereo 音声接続の競合判定をネイティブ側の保証範囲に合わせる

- Branch: feature/add-stereo-audio-output
- Polished: {YYYY-MM-DD}

## 目的

ネイティブ側の共有設定の改善を取り込み、安全に動作できる音声接続まで一律に拒否しないようにする。

## 現状

調査対象は PR #381 のコミット `16cba6346931d9d631e7061cb5632d193c1a2cb8` と libwebrtc `m150.7871.3.2` である。

- `AudioSessionCoordinator` は Sora インスタンス間で AudioSession の利用プロファイルを管理する。
- `.stereoRemoteIO` は他の stereo、VoiceProcessingIO、カスタム音声デバイスによる音声接続と排他になっている。
- webrtc-build の stereo 実装は、設定適用時に共有設定の mode を一時変更する。SDK 内の排他では、ホストアプリや他の SDK による変更は制御できない。
- 一時変更をなくしても、AVAudioSession の mode や category がプロセスで共有されることと、複数 AudioUnit の動作制約は残る。

## 設計方針

- webrtc-build issue 0013 の成果を取り込み、mono / stereo / カスタム音声デバイスと送受信方向の組み合わせについて、許可条件と拒否理由を整理する。
- 同時動作を実機で確認できた組み合わせに限って制限を緩和する。共有設定をコピーする変更だけを根拠に排他やロックを削除しない。
- 同じ stereo プロファイル同士も、複数 ADM と AudioUnit の同時動作を確認してから判断する。
- カスタム音声デバイスは、ホストの AudioSession 利用に関する契約が明確な範囲で判断する。
- ホストが共有設定を置換した場合や最後の利用者が終了した場合に、外部の変更を古い値で上書きしない。
- 安全性を確認できない組み合わせは拒否を維持し、制約と理由を公開設定の説明へ反映する。

## 対応ブランチと依存関係

ユーザー指定の例外として、PR #381 の `feature/add-stereo-audio-output` に含める。
webrtc-build の `feature/m150.7871` で issue 0013 を先に対応する。
受信専用プロファイルを追加する issue 0133 と、競合判定の分類を揃える。
一般的な Sora 共有状態の整理を扱う既存 issue 0111 へ範囲を広げない。

## テスト方針

利用要求の取得・解放と競合判定を検証し、許可する組み合わせは実際の ADM と実機で同時再生・送受信を確認する。
開始順と終了順の入れ替え、失敗後の解放、外部設定の置換を含める。
モックやスタブは使用しない。

## 完了条件

- プロファイルの組み合わせごとに許可・拒否と根拠が記録されている。
- 安全性を確認できた組み合わせが許可され、確認できない組み合わせの拒否は維持される。
- 緩和できる組み合わせがなかった場合も、確認した条件と制約を記録し、根拠なく排他を削除しない。
- 開始・終了順や失敗によって利用要求が残らず、外部で変更した共有設定を壊さない。
- 公開設定の説明と実装・検証結果が一致する。
