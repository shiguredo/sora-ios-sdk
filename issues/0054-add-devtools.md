## 概要

iOS SDK の開発・デバッグを支援する DevTools 機能を作成する。接続状態・統計情報・シグナリングメッセージなどを可視化・操作できる仕組みを提供する。

## 背景

現状は SDK の内部状態やシグナリングの詳細を確認するためにログを読む以外の手段がなく、デバッグ・動作確認に手間がかかる。DevTools として統計情報の可視化や接続パラメーターの確認手段を用意することで、開発効率と問題解決速度を向上させる。

## 実装方針

- SDK のターゲットに組み込むか、別モジュールとして切り出すかを設計時に検討する
- デバッグビルド時のみ有効になる仕組みを優先する
- リリースビルドへの影響がないよう注意する

## 提供候補機能

- `getStats` 結果の構造化・表示（`0048` の RTCRtpCodecCapability ログ出力とも連携）
- シグナリングメッセージのログ表示（送受信の JSON を閲覧できる）
- 接続パラメーター（`Configuration` の内容）の確認
- ICE 接続状態・候補の確認

## 根拠

Sora サーバー側は DevTools を備えており、クライアント側にも同等のデバッグ手段があることで問題の切り分けがしやすくなる。ユーザーからのバグ報告の質向上にも貢献できる。

## 検証ツール (sora-ios-sdk-devtools) の開発計画

### 契機

iOS SDK の機能検証を行いたいが、sora-ios-sdk-samples に検証用の機能を足し続けるのは望ましくない。samples は機能を軽く試したり実装の参考にするためのサンプルであり、検証のためにあるものではない。検証専用のツール (devtools) を分けて用意する。

基本コンセプトは他の Sora クライアント SDK の devtools と揃え、SDK が提供する機能をひととおり確認できるものとする。いきなり全機能を用意するのではなく、検証のたびに項目を追加していく。

### 方針

- `sora-ios-sdk-devtools` リポジトリを新設し、検証ツールをそこへ集約する
- SDK 本体には検証用途のコードを入れず、samples にも検証機能を足さない
- SDK の開発版ブランチを試験しやすい構成にする

### 作成するもの

- `sora-ios-sdk-devtools` リポジトリを新設する
- 次の既存サンプルをマージした検証ツールを作成する
  - DataChannelSample
  - SimulcastSample
  - SpotlightSample
  - VideoChatSample
- 接続中の操作を行えるようにする
  - 接続 / 切断
  - 映像のミュート / アンミュート
  - 音声のミュート / アンミュート
  - データチャネルメッセージの送信
- 接続情報を表示できるようにする
  - connection_id
  - 受信映像の解像度
  - 音量
- Android 版 devtools のサンプルを参考に、不足している検証項目を追加する
  - サンプルでビットレートを指定できるようにしたいという要望
  - サンプルに音声ミュート・ビデオミュートのボタンを追加したいという要望
- サンプルアプリの設計は Twilio のサンプルを参考にする

### サンプル側の整理

検証用途の機能を devtools へ移したうえで、sora-ios-sdk-samples から不要な機能を削り、ビデオチャットアプリ 1 種類に集約する。samples の構成見直しは別途 issue として扱う。
